# Repair Codex Hook Registry

## Overview

Repair `.codex/hooks.json` so new Codex sessions load the expected ClaudeKit safety hooks again. Use `.codex/hooks.json.2026-07-06T17-00-56.bak` as the baseline, then evaluate missing Claude-side events from `.claude/settings.json` and add only the events Codex actually supports. Where Codex lacks an event, implement an explicit wrapper or document the gap instead of pretending the hook is active.

This plan only covers Codex hook configuration and supporting Codex-side hook wrappers. It does not change `.claude/settings.json`, application code, Django runtime services, or assignment features.

## Current Findings

- Before repair, `.codex/hooks.json` only registered `UserPromptSubmit` through `.codex/hooks/ddbf865c-simplify-gate.cjs`.
- Backup `.codex/hooks.json.2026-07-06T17-00-56.bak` also registered `PreToolUse` hooks for `descriptive-name`, `scout-block`, and `privacy-block`.
- `.codex/hooks/` already contains direct scripts for `simplify-gate.cjs`, `descriptive-name.cjs`, `scout-block.cjs`, and `privacy-block.cjs`.
- `.claude/settings.json` contains additional Claude Code events: `Notification`, `SessionStart`, `SubagentStart`, `PostToolUse`, `SubagentStop`, and `Stop`.
- The repaired `.codex/hooks.json` restores baseline `PreToolUse` and adds Codex `command_execution` matching for shell actions.
- Referenced Codex wrappers emit the v0.151.0-compatible schema: `decision: "block"` for blocking `PreToolUse` hooks and `additional_context` for descriptive-name context.
- Fresh interactive Codex CLI validation passed after trusting changed hooks: an attempted ignored dependency-path read was blocked by `PreToolUse` before command execution.
- `UserPromptSubmit` is registered and manually verified, but fresh-session blocking was not proven because this checkout does not enable the simplify gate threshold in `.ck.json` or `.codex/.ck.json`.
- Hash-named wrappers are generated by `ck migrate` but manually patched for Codex CLI v0.151.0 schema; do not regenerate until the migration template emits the same schema.
- Non-interactive `codex exec --json` did not fire project `PreToolUse` in the same scenario; keep that runtime path documented as a limitation.
- There is no verified Codex support yet for direct `PermissionRequest`, `Stop`, `SessionStart`, `SubagentStart`, `SubagentStop`, or `PostToolUse` registrations in this project registry.

## Scope

- Restore Codex baseline safety hooks from the backup structure.
- Prefer stable, direct `.codex/hooks/*.cjs` paths unless Codex requires generated wrappers.
- Audit which hook events Codex supports before adding new event registrations.
- Add verified missing hooks, or build small Codex-side adapters when the host lacks the event.
- Add verification steps proving new sessions load the intended hooks.

Out of scope:

- Changing Claude Code hook behavior.
- Editing machine-local secret or notification provider env files.
- Adding new external notification providers.
- Refactoring hook internals without a failing verification.
