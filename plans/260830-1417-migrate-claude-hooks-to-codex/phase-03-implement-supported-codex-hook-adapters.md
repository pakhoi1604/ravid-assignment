# Phase 3: Implement Supported Codex Hook Adapters

## Overview

Add Codex hook registrations and explicit adapters for the missing Claude-declared behavior. Native registrations are allowed only for events proven in Phase 1; unsupported lifecycle behavior must move to explicit adapter boundaries.

## Requirements

- Functional: add missing `UserPromptSubmit` hooks where Codex supports equivalent behavior.
- Functional: add `PostToolUse`, `SessionStart`, `PermissionRequest`, or `Stop` only if runtime-proven.
- Functional: support subagent context injection for Codex if native `SubagentStart` exists or via `spawn_agent` adapter if not.
- Functional: support subagent/session completion state refresh if native `SubagentStop` exists or via `wait`/`close_agent` adapter if not.
- Non-functional: no dead `.codex/hooks.json` entries.
- Non-functional: hook/adapters must fail open unless they enforce privacy/scout safety.

## Architecture

Use two paths:

1. Native hook path: `.codex/hooks.json` event -> wrapper -> existing hook library.
2. Adapter path: Codex collaboration boundary -> context/state helper -> `spawn_agent`, `wait`, or shutdown action.

If Codex does not emit lifecycle hook events, the adapter path is the only honest way to match Claude behavior.

## Related Code Files

- Modify: `.codex/hooks.json`
- Modify/Create: `.codex/hooks/*` wrappers for proven native events
- Modify/Create: `.codex/hooks/lib/*` shared helpers if needed
- Modify/Create: Codex-side subagent adapter path if an existing controller/wrapper exists in repo
- Modify: `.codex/hooks-support.md`
- Do not modify: `.claude/settings.json`

## Implementation Steps

1. Extend `UserPromptSubmit` only after schema checks:
   - consider `dev-rules-reminder`
   - consider `usage-quota-cache-refresh`
   - keep `simplify-gate` behavior intact
2. Add `Notification` equivalent only if Codex `PermissionRequest` fresh runtime firing is proven.
3. Add `SessionStart` equivalent only if fresh runtime payload supports startup/resume/compact semantics.
4. Add `PostToolUse` native hooks only if Codex fires them:
   - `Edit|Write|MultiEdit` -> `plan-format-kanban`
   - task tools -> `session-state`, `usage-quota-cache-refresh`
5. For subagent start:
   - if native `SubagentStart` fires, register wrapper for `subagent-init`.
   - otherwise design a `spawn_agent` adapter that prepends the context generated by `subagent-init` to the child prompt.
6. For subagent stop:
   - if native `SubagentStop` fires, register wrappers for `cook-after-plan-reminder` and `session-state`.
   - otherwise refresh state after `wait`/`close_agent` returns child completion data.
7. For `Stop`:
   - register native hook only if fresh session shutdown proves runtime firing.
   - otherwise document manual/session-state fallback.
8. Keep `.codex/hooks.json` comments out of JSON; put rationale in `.codex/hooks-support.md`.

## Success Criteria

- [ ] `.codex/hooks.json` contains no unproven event registrations.
- [ ] All registered command paths exist and pass representative payload checks.
- [ ] Subagent context is injected through native hook or explicit adapter.
- [ ] Subagent/session state is refreshed through native hook or explicit adapter.
- [ ] Unsupported events are documented with exact fallback behavior.

## Risk Assessment

Risk: an adapter around `spawn_agent` may not be possible from project files if Codex collaboration tools are host-provided only. Mitigation: document host limitation and keep behavior explicit in agent instructions until Codex exposes an extension point.

Risk: task/session hooks can write state files in unexpected locations. Mitigation: use existing `session-state` libraries and verify outputs in `/tmp` before enabling in repo.
