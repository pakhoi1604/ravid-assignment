## Actual Pipeline and Interfaces

1. **Auth and public routes.** JWT obtain/refresh are `/api/auth/token/` and `/api/auth/token/refresh/`; upload/status/chat require the global JWT authentication policy, while health/schema/docs explicitly remain public (`config/urls.py:7`, `config/settings/base.py:100`, `config/urls.py:14`). Existing auth tests cover valid obtain/refresh, invalid credentials, and unauthenticated upload (`tests/accounts/test_auth.py:8`, `tests/accounts/test_auth.py:40`, `tests/accounts/test_auth.py:56`).
2. **Upload validation and atomic persistence.** `UploadSerializer` accepts only configured extensions and caps declared size (`apps/documents/serializers.py:12`). `DocumentUploadView` creates `Document`, `IngestionJob`, and `IngestionDispatch` in one DB transaction; the file is deleted when a post-save exception escapes (`apps/documents/views.py:42`, `apps/documents/views.py:50`, `apps/documents/views.py:60`). The model sanitizes the basename and scopes storage by owner/public UUID (`apps/documents/models.py:9`). API tests cover the happy DB rows, invalid extension, missing file, and oversized file (`tests/documents/test_api.py:35`, `tests/documents/test_api.py:63`, `tests/documents/test_api.py:77`, `tests/documents/test_api.py:85`).
3. **Transactional outbox to Celery.** Dispatch creation snapshots the job generation (`apps/documents/dispatch.py:11`). A publisher claims due rows with `select_for_update(skip_locked=True)`, increments attempts, publishes outside the transaction, then compare-and-swaps the claim to `PUBLISHED`, retry, or `DEAD` (`apps/documents/dispatch.py:38`, `apps/documents/dispatch.py:67`). Beat schedules publishing every configured interval (`config/settings/base.py:132`). Unit tests cover creation, lease, successful publish, expired reset, and exhausted expired claim (`tests/documents/test_dispatch.py:29`, `tests/documents/test_dispatch.py:38`, `tests/documents/test_dispatch.py:52`, `tests/documents/test_dispatch.py:68`, `tests/documents/test_dispatch.py:82`).
4. **Worker claim and status lifecycle.** Enqueue uses the stable job task UUID and generation as arguments but a unique Celery delivery ID (`apps/documents/tasks.py:23`). The worker atomically claims only `PENDING` plus matching generation, sets `PROCESSING` and lease, runs ingestion, then activates success or records sanitized failure (`apps/documents/tasks.py:32`, `apps/documents/tasks.py:72`, `apps/documents/tasks.py:130`, `apps/documents/tasks.py:183`). Tests cover success/failure, unknown/malformed ID, duplicate success, and mismatched generation (`tests/documents/test_tasks.py:24`, `tests/documents/test_tasks.py:42`, `tests/documents/test_tasks.py:61`, `tests/documents/test_tasks.py:85`, `tests/documents/test_tasks.py:97`).
5. **Extract, chunk, embed, verify, activate.** Ingestion creates a `WRITING` generation manifest, extracts within page/character limits, chunks within count limits, attaches trusted owner/document/generation metadata, writes and reads back Chroma, then records observed count (`apps/documents/ingestion.py:9`, `apps/documents/ingestion.py:21`, `apps/documents/ingestion.py:30`, `apps/documents/ingestion.py:39`, `apps/documents/ingestion.py:56`). TXT/MD require UTF-8; PDF uses `pypdf` and bounds pages/chars (`apps/documents/extraction.py:7`, `apps/documents/extraction.py:22`, `apps/documents/extraction.py:35`). Chunking uses `RecursiveCharacterTextSplitter` and rejects over-limit materialization (`apps/documents/chunking.py:4`). Chroma validates metadata/IDs before write and verifies exact IDs/metadata after write (`apps/documents/vector_store.py:166`, `apps/documents/vector_store.py:311`, `apps/documents/vector_store.py:382`). Activation is a PostgreSQL transaction and only succeeds for the still-current processing generation; the previous active generation becomes delayed-cleanup `STALE` (`apps/documents/tasks.py:72`).
6. **Status.** Status lookup requires `task_id`, scopes the job to the authenticated owner, returns `404` for malformed/foreign IDs, and serializes stable status-specific messages (`apps/documents/views.py:74`, `apps/documents/serializers.py:46`). Existing tests cover pending, success/failure shapes, owner isolation, missing and malformed IDs (`tests/documents/test_api.py:98`, `tests/documents/test_api.py:119`, `tests/documents/test_api.py:164`, `tests/documents/test_api.py:184`, `tests/documents/test_api.py:192`).
7. **Generation-safe retrieval.** PostgreSQL first resolves the owner's non-null active `(document_id, generation)` map, Chroma receives only active generations, and returned document/generation pairs are revalidated (`apps/documents/retrieval.py:25`). Chroma also filters by exact integer `user_id` plus generation and fails closed on untrusted result metadata (`apps/documents/vector_store.py:43`, `apps/documents/vector_store.py:273`). Unit tests cover active generation propagation, empty active set, and wrong pair rejection (`tests/documents/test_retrieval.py:13`, `tests/documents/test_retrieval.py:51`, `tests/documents/test_retrieval.py:67`).
8. **Standard RAG and HyDE.** Request input is strict UTF-8 text up to 2,000 chars and a strict boolean toggle (`apps/rag/serializers.py:4`, `apps/rag/serializers.py:16`, `apps/rag/serializers.py:23`). `RagService` checks subscription, OpenRouter/free-model configuration, and retrieval settings before optional HyDE (`apps/rag/services.py:241`, `apps/rag/llm.py:13`). Standard retrieval uses the original question; HyDE reserves quota, creates a bounded hypothetical with a shorter timeout, retrieves using it, but final synthesis receives the original question and real chunks only (`apps/rag/services.py:123`, `apps/rag/services.py:241`, `apps/rag/services.py:298`). Expected HyDE transport/invalid output falls back to standard; empty retrieval returns a fixed answer without final generation (`apps/rag/services.py:145`, `apps/rag/services.py:155`, `apps/rag/services.py:284`). Context and returned excerpts share the same hard character bound (`apps/rag/prompts.py:52`, `apps/rag/services.py:205`).
9. **Quota and provider boundary.** Subscription/quota rows are transactionally locked; reserve rejects over-limit requests and finalize/refund reconcile the reservation (`apps/accounts/entitlements.py:61`, `apps/accounts/entitlements.py:93`, `apps/accounts/entitlements.py:100`). Each RAG stage allows one terminal settlement attempt (`apps/rag/accounting.py:12`). OpenRouter enforces free-tier model, positive timeout, zero retries, and translates only known transport/provider errors (`apps/rag/llm.py:13`, `apps/rag/llm.py:30`, `apps/rag/llm.py:74`). Service tests cover HyDE success/fallback, timeout charge, retrieval failure, final refund, empty retrieval, quota rejection, invalid usage, invalid settings, programming errors, and accounting errors (`tests/rag/test_services.py:237`, `tests/rag/test_services.py:287`, `tests/rag/test_services.py:334`, `tests/rag/test_services.py:372`, `tests/rag/test_services.py:400`, `tests/rag/test_services.py:427`, `tests/rag/test_services.py:449`, `tests/rag/test_services.py:487`, `tests/rag/test_services.py:535`, `tests/rag/test_services.py:563`).
10. **Runtime topology and docs.** Compose runs web, Celery, Beat, PostgreSQL, Redis, Chroma, and Flower; web/worker share media and model cache, and only web receives OpenRouter credentials (`compose.yaml:1`, `compose.yaml:66`, `compose.yaml:110`, `compose.yaml:162`, `compose.yaml:196`, `compose.yaml:210`, `compose.yaml:218`, `compose.yaml:231`). Health probes cover web, worker, db, Redis, and Chroma (`compose.yaml:76`, `compose.yaml:156`, `compose.yaml:204`, `compose.yaml:212`, `compose.yaml:225`). Schema tests assert upload multipart/binary and chat/HyDE response contracts (`tests/smoke/test_health.py:11`); Compose tests are static YAML/Dockerfile assertions, not running-service tests (`tests/smoke/test_compose_contracts.py:8`).

## Recommended Test Lanes and Commands

1. **Fast deterministic gate:** `uv run ruff check apps config tests`; `uv run python manage.py check --settings=config.settings.test`; `uv run python manage.py makemigrations --check --dry-run --settings=config.settings.test`; `uv run pytest -q`. These correspond to repository wrappers (`Makefile:6`, `Makefile:9`, `Makefile:15`, `Makefile:18`).
2. **Coverage/gap gate:** `uv run pytest --cov=apps --cov=config --cov-branch --cov-report=term-missing`; branch coverage is configured for apps/config (`pyproject.toml:61`). Set an explicit threshold only after recording the current baseline; prioritize the P0 transitions above over a global percentage.
3. **Production database and Chroma invariants:** `docker compose --profile test build test`; `docker compose --profile test up -d db chroma`; then run the PostgreSQL quota test and repaired generation-aware Chroma test using `--ds=config.settings.production` (`README.md:224`). The current `test` service depends only on db/chroma, so it cannot validate Redis/Celery delivery (`compose.yaml:82`, `compose.yaml:104`).
4. **Full offline Compose pipeline:** `docker compose up -d --build`; load accounts; POST JWT/upload; poll status with a bounded timeout; query standard and HyDE using a local deterministic provider seam; query as a second owner; inspect PostgreSQL and Chroma invariants; run `make smoke`; retain service logs on failure. Reviewer commands and fixture are documented at `README.md:27`, `README.md:51`, `README.md:61`, `README.md:75`; infrastructure smoke is `Makefile:41`.
5. **Fault-injection lane:** while a synthetic job is at each transition, stop/restart Redis, Celery, and Chroma separately; expire outbox/worker leases; redeliver identical and stale generations; assert eventual state plus no cross-owner/stale visibility. At-least-once and lack of cross-system transaction are explicit limitations (`docs/system-architecture.md:161`).
6. **Optional live OpenRouter lane:** require an explicit opt-in environment marker and API key; use only `tests/fixtures/rag/reviewer-handbook.md`; run one standard and one HyDE request, assert contract/grounding rather than exact prose, and never log chunks/provider key. The synthetic-only privacy constraint is explicit (`docs/system-architecture.md:139`) and credentials exist only in web (`compose.yaml:25`, `tests/smoke/test_compose_contracts.py:73`).

## Exit Criteria for a Credible Full-Pipeline Gate

- Fresh Compose stack becomes healthy, migrations and account seed are repeatable, and public health/schema/docs contracts pass (`compose.yaml:8`, `tests/smoke/test_health.py:4`).
- Authenticated MD/TXT/PDF uploads traverse a real outbox and worker to `SUCCESS`; invalid/corrupt/over-limit inputs terminate safely at `FAILURE`, never activate partial generations, and remain owner-scoped (`apps/documents/views.py:50`, `apps/documents/tasks.py:72`).
- Real Chroma retrieval exposes only the authenticated owner's active document-generation pairs, including after re-ingest, duplicate delivery, recovery, and cleanup (`apps/documents/retrieval.py:35`, `apps/documents/recovery.py:100`).
- Standard and HyDE paths use real retrieved chunks, preserve the original final question, exercise fallback/no-context/quota/provider failures, and return schema-valid metadata (`apps/rag/services.py:241`, `tests/smoke/test_health.py:44`).
- The deterministic suite remains green, production-backed invariant gates contain no skips, and fault-injection cases have bounded waits plus captured container/application state on failure.
