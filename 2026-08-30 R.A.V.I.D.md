## Part 3 (Bonus) Advanced Retrieval with HyDE (Hypothetical Document Embeddings)

Standard vector search compares the raw user query vector directly against indexed document vectors. Because questions and answers often differ significantly in length, syntax, and vocabulary, direct semantic matching can produce suboptimal similarity scores.

In this bonus section, candidates will implement HyDE (Hypothetical Document Embeddings) to bridge this semantic gap and elevate retrieval accuracy.

Gao et al., "Precise Zero-Shot Dense Retrieval without Relevance Labels" (ACL 2023) — arXiv:2212.10496 - https://arxiv.org/pdf/2212.10496 [URL 🔗](https://arxiv.org/pdf/2212.10496)

## How HyDE Works in this Workflow

- 1. Hypothetical Generation: When a user submits a query, prompt an LLM (via OpenRouter) to draft a hypothetical, ideal passage that directly answers the question—even if hallucinated or factually approximate.

- 2. Hypothetical Vector Embedding: Embed this generated hypothetical document rather than the short raw query. The resulting vector captures domain-specific context and expected answer phrasing.

- 3. Enhanced Vector Search: Use the hypothetical document's embedding to query the vector store, retrieving the true source chunks with higher semantic alignment.

- 4. Final RAG Synthesis: Pass the retrieved real source context and the original question to the final LLM to generate the verified answer.
