# Codex Hook Support

## Active Registry

`.codex/hooks.json` is the active Codex hook registry for this project.
It intentionally uses Codex compatibility wrappers when a hook may block a tool call.

Configured events:

- `UserPromptSubmit` -> `simplify-gate`
- `PreToolUse` -> `descriptive-name`, `scout-block`, `privacy-block`

The `PreToolUse` registry keeps the restored Claude-style matcher names and also includes
`command_execution`, which is the tool action name observed from Codex CLI v0.151.0 interactive
sessions for shell commands.

## Claude Events Not Directly Mirrored

`.claude/settings.json` remains the Claude Code registry. Do not assume those hooks fire in Codex.

Known gaps:

- `Notification`: Claude Code event. Codex equivalent is represented here as `PermissionRequest` for approval prompts only.
- `SessionStart`: not registered until Codex support and payload behavior are verified.
- `SubagentStart`: not registered. Current Codex `collaboration.spawn_agent` does not prove support for hook-based context injection.
- `SubagentStop`: not registered until Codex support is verified.
- `PostToolUse`: not registered until Codex support is verified.
- `PermissionRequest`: not registered until a fresh Codex session proves the event fires for approval prompts.
- `Stop`: not registered until a fresh Codex session proves the event fires on session shutdown.

## Verification Rule

Every hook listed in `.codex/hooks.json` must satisfy both checks:

1. The command path exists and handles a representative JSON payload.
2. Safety-blocking hooks must be proven in a fresh interactive Codex session before they are treated as enforced.

## Current Verification

Static and manual payload checks pass for the registered commands:

- `UserPromptSubmit` `simplify-gate`: wrapper exits cleanly with a benign prompt.
- `PreToolUse` `descriptive-name`: wrapper returns Codex `additional_context` for `Write`.
- `PreToolUse` `privacy-block`: wrapper returns Codex JSON `decision: "block"` for sensitive dotenv paths.
- `PreToolUse` `scout-block`: wrapper returns Codex JSON `decision: "block"` for ignored dependency paths.
- `PermissionRequest` and `Stop`: manual script checks passed during investigation, but runtime firing was not proven. They are intentionally not registered in `.codex/hooks.json`.

Fresh interactive-session activation passed on Codex CLI v0.151.0:

- Codex loaded `.codex/hooks.json`, prompted to trust changed hooks, then `PreToolUse`
  blocked a shell command that tried to read an ignored dependency path.

`UserPromptSubmit` is registered and manually verified, but fresh-session blocking was not proven
because this checkout does not enable the simplify gate threshold in `.ck.json` or `.codex/.ck.json`.

Wrapper maintenance note:

- The hash-named wrappers were generated by `ck migrate`, then manually patched for Codex CLI
  v0.151.0 output schema. Do not regenerate them until the migration template emits
  `decision: "block"` for `PreToolUse` blocks and `additional_context` for context injection.

Observed limitation:

- `codex exec --json` did not fire the project `PreToolUse` hook in the same ignored-path scenario, even with hook trust bypass enabled. Treat `codex exec` hook coverage as unverified for this runtime.
